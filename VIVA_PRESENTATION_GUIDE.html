4. Role-Based Access Control (RBAC)

Our system strictly manages permissions across 3 tiers of users:

1
SuperAdmin
Full campus authority. Manages departments, blocks, rooms, users, assigns staff, and exports reports.
2
Field Technicians
Electrician, Plumber, Network, Hardware. Views assigned tickets and updates status to In-Progress / Resolved.
3
End Users
Students, faculty, staff. Raises tickets with photo evidence, tracks status, and submits 1-5 star ratings.

6. Most Frequently Asked Viva Questions & Answers

Q1: What is the main purpose of this project?
Answer: The main purpose is to automate and streamline campus facility maintenance by replacing paper-based complaints with an online ticketing platform supporting real-time tracking, photo attachments, and staff assignments across web and mobile.
Q2: Why did you choose MERN stack instead of traditional PHP/MySQL or Java?
Answer: MERN uses JavaScript end-to-end across frontend, backend, and database queries. It provides high performance with Node's non-blocking I/O, rapid UI updates with React's Virtual DOM, and schema flexibility with MongoDB.
Q3: How is authentication handled in your project?
Answer: We use JWT (JSON Web Tokens). When a user logs in with email and password, the server validates password using bcrypt.compare(). If valid, the server signs a JWT containing the user ID, email, and role. The client stores this token in localStorage/SecureStore and sends it in the HTTP Authorization: Bearer <token> header for subsequent API requests.
Q4: How do you handle password security?
Answer: Passwords are never stored in plain text. We hash them using bcryptjs with 10 salt rounds before saving to MongoDB. Even database administrators cannot see the raw passwords.
Q5: What database collections (models) do you have?
Answer: We have 6 main collections in MongoDB: User (credentials, role, department), Complaint (ticket title, category, block, room, status, priority, attachment), Department, Programme, Block, and Room.
Q6: How do file uploads work for ticket attachments?
Answer: We use Multer middleware on Express. Multer intercepts multipart/form-data requests, renames the uploaded image with a unique timestamp, and stores it in the server's /uploads directory while saving the relative file path in the MongoDB document.
Q7: How does the Mobile App communicate with the Backend?
Answer: The React Native mobile app communicates with the Node.js backend using Axios HTTP requests pointing to our REST API endpoint (e.g. https://tms-1-ful8.onrender.com/api). It stores the session token using Expo SecureStore on mobile and localStorage on web.
Q8: What is Expo SDK 58 and why did you use it?
Answer: Expo is a modern React Native framework that provides native modules for camera, file system, document picker, and secure storage without needing complex native Xcode or Android Studio configurations. SDK 58 uses the latest React Native 0.88 with improved performance.
Q9: What challenges did you face during development?
Answer: Three main challenges: 1. Configuring cross-platform storage so that token storage works on both mobile native hardware and web browsers. 2. Managing cascading dropdowns (selecting a department filters the blocks, which then filters rooms). 3. Protecting routes using middleware so unauthorized users cannot access SuperAdmin management panels.
Q10: What are the future enhancements for this project?
Answer: Future enhancements include push notifications via Firebase Cloud Messaging, AI-based automatic complaint classification, SLA (Service Level Agreement) breach countdown timers, and QR code stickers on classroom doors for instant room ticket scanning.
